3 · Netlify (hosting + functions)

  • One Netlify site serves both: the product at asap.tools and this PRD (the prd-site/ folder) at asap.tools/prd. The site deploys from the GitHub repo.
  • Product build: static assets + netlify/functions/*; env vars per context (Supabase URL/keys, Google client, Resend key); deploy previews get the staging Supabase project.

4 · v2 media layer — deferred, decision wk 6

Decision date: end of week 6 (v1 launch), from the wk 4–6 spike readout. Owner: infra eng. The spike prototypes join-by-drag latency inside the live graph for both SDK options.

OptionForAgainst
Daily (SDK)Fastest embed; prebuilt UI escape hatch; recording API for 2e async recaps.Per-minute cost scales with blob dwell time; less layout control inside the blob ring.
LiveKit CloudDeep UI control (tiles inside the blob), open-source exit ramp, good data channels for presence.More integration work; recording pipeline is ours to assemble.
Meet/Zoom linksNear-zero build; blob is just a door.Breaks the core v2 promise — join-by-drag becomes join-by-new-tab; no presence inside the blob; ruled out unless spike fails both SDKs.
  • Decision criteria, in order: (1) drag-in → media-connected < 2s, (2) presence fidelity (who's inside, live, from the graph), (3) recording for the 2e async contract, (4) cost per active blob-hour.
  • Whatever wins, the blob contract is fixed by the v1 groundwork: solid ring = enterable, × closes and folds artifacts back, membership changes go through graph_nodes.

5 · Explicitly not integrated in v1

  • Outlook / CalDAV / ICS export — Google-only by decision; revisit with demand data post-launch.
  • Slack, push, SMS — email is the only channel; the orb is the in-app channel.
  • Any LLM API — the AI is the deterministic scorer + motion; there is nothing to call.
